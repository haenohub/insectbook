# 서치! 곤충도감

저장된 색연필 손그림과 국립수목원 곤충도감 원문을 연결한 반응형 웹페이지입니다. 현재 스냅샷은 실제 생성된 **800종**을 포함합니다. 이번에 추가한 79종의 그림은 종별 정보·타이틀·게임 능력치·보스전 스킬에 연결됩니다. 요청한 79종 생성 작업은 완료했으며, 추가 요청 전에는 다음 그림을 생성하지 않습니다.

## 실행

Node.js 22.12 이상을 사용합니다.

```sh
npm ci
npm run dev
```

개발 서버는 클라우드 안의 `http://localhost:5173`에서 실행됩니다. 개인 컴퓨터의 `localhost` 주소는 이 서버에 연결되지 않습니다. 새 클라우드 세션에서는 `npm run dev`를 다시 실행하고 5173번 포트의 미리보기를 이용하세요.

GitHub Pages 배포 주소: **https://haenohub.github.io/insectbook/**. 배포 성공 여부는 저장소의 [Actions](https://github.com/haenohub/insectbook/actions/workflows/deploy-pages.yml)에서 확인합니다.

```sh
npm run build
npm run preview
```

`dist/`는 정적 웹사이트입니다. 배포에는 원본 PNG에서 자르지 않고 만든 WebP 사본(최대 1280px, 품질 90)과 연결된 원문 JSON을 사용합니다. 현재 800장 사본은 약 102MiB로 GitHub Pages 용량 제한 안에 들어갑니다. PNG 원본과 이전 수정본은 클라우드의 `assets/illustrations/`에 보존하며 Git에는 포함하지 않습니다. 배포용 WebP와 원본·사본 해시는 `assets/web-illustrations/manifest.json`으로 관리합니다.

## GitHub Pages 배포

`main`에 push하면 `.github/workflows/deploy-pages.yml`이 의존성 설치, 테스트, `/insectbook/` 경로 빌드, 저장된 전체 그림과 원문 파일 검증, Pages 배포를 수행합니다. 저장소 **Settings → Pages → Build and deployment → Source**는 **GitHub Actions**를 사용합니다. 최초 자동 설정에 권한이 부족하면 이 항목을 직접 선택하고 Actions에서 워크플로를 다시 실행하세요.

Git에 저장된 WebP만으로 빌드할 수 있어 전체 PNG 원본을 내려받을 필요가 없습니다. 클라우드에서 그림을 추가한 뒤에는 `npm run prepare:images`로 배포 사본을 갱신하세요. 이 명령은 원본 PNG가 있는 환경에서만 실행합니다.

```sh
VITE_BASE_PATH=/insectbook/ npm run build
npm run verify:build
VITE_BASE_PATH=/insectbook/ npm run preview -- --port 4173
```

이 빌드의 미리보기 경로는 `/insectbook/`입니다. 루트 경로에 배포하려면 `VITE_BASE_PATH` 없이 빌드하세요. 네트워크가 제한된 클라우드에서는 GitHub API 확인에 `api.github.com`, 게시 사이트 확인에 `haenohub.github.io` 허용이 필요합니다.

## 기능

- 한국어 이름·학명·과·속·특징 타이틀 통합 검색 및 검색 범위 선택. 라틴명은 대소문자를 구분하지 않으며 타이틀은 띄어쓰기 없이도 검색할 수 있습니다.
- 과·속 필터, 17개 타이틀, 복수 타이틀 교집합, 능력치 정렬과 페이지 이동. 검색 조건은 URL에 반영되어 새로고침 후에도 유지됩니다.
- 손그림 상세, 분류 정보, 원문 관찰 노트와 국립수목원 출처 링크. 설명 조회 실패 시 재시도할 수 있습니다.
- 타이틀별 부여 이유와 원문/분류/공통 게임 별명 구분. 설명이 부족할 때는 종별 생태를 임의로 지어내지 않고 공통 게임 별명을 사용합니다.
- 로컬 관찰함, 서로 다른 곤충 세 마리의 탐험대 구성과 랜덤 팀 구성, 800종 전체 검색으로 팀원 선택.
- HP·공격력·방어력·민첩성·회피율과 17종 타이틀 스킬. 직접 행동 선택, 아군 지정 회복·보호막, 보스 행동 예고와 공략 노트, 10개 스테이지, 3배속 및 현재 턴 결과 건너뛰기.
- 모바일 필터 패널, 상세 대화상자, 선택 트레이와 배틀 화면. 동작 줄이기 설정을 따릅니다.

관찰함은 해당 브라우저의 `localStorage`에 보관합니다. 보스전 진행은 현재 탭의 메모리에서 유지되므로 도감으로 이동했다 돌아와도 이어지며, 새로고침하면 처음부터 시작합니다. 과거 1:1 대결 저장 키는 삭제하지 않으며 새 보스전에 사용하지 않습니다.

## 데이터와 타이틀

추가 79종의 완료 목록과 참조 사진 검토 결과는 `data/illustration-run.json`과 `data/illustration-additional79-results.json`에 있습니다. 원본에서 전신 형태를 확인하기 어려운 5종은 보류하고 다음 순서의 곤충으로 대체했습니다. 이전 550종 작업 기록은 `data/illustration-runs/additional-550-total-1000.json`에 보존했습니다.

`scripts/build-web-data.mjs`는 수집 데이터의 `generated` 또는 `approved` 상태이면서 실제 파일이 있고 `blocked`가 아닌 항목만 읽습니다. 원본을 바꾸지 않고 `data/web-catalog.json`을 생성합니다. `npm run dev`와 `npm run build`에서 자동 실행하므로 이후 그림이 늘어나면 현재 저장 목록을 다시 반영할 수 있습니다.

타이틀과 스탯 규칙은 `src/lib/profiles.mjs`에 있습니다. 예를 들어 원문의 월동 기록은 생존왕, 보호색·의태 기록은 위장술사에 연결됩니다. 몸 크기는 `몸길이`와 `체장`에서 mm/cm를 읽으며 날개편 길이는 몸길이로 쓰지 않습니다. 알려진 몸 크기가 없으면 분류군 기본값을 사용합니다. 분류에서 착안한 별명은 종별 식성·측정 성능을 확정하는 주장이 아닙니다. 이름에 들어간 ‘벌’ 등의 문자열만으로 생태를 추정하지 않습니다.

스탯은 분류군 기본값에 기록된 몸 크기와 타이틀 보정을 더한 **게임 규칙**입니다. 실제 생물의 성능 측정값이나 우열을 뜻하지 않습니다. 생물종 원문에는 정보량·사진 품질 차이가 있으며 손그림은 기존 생성본을 사용합니다. 과거 생성 검토 사항은 `data/illustration-review.json`에 보존되어 있습니다.

## 3인 보스 도전

기존 자동 1:1 화면을 세 곤충으로 열 보스를 순서대로 클리어하는 턴제 보스전으로 교체했습니다. 도감의 카드·상세에서 세 마리를 고르거나 보스 도전 화면에서 팀을 구성합니다. 중복 선택은 막으며 진행 중에는 팀이 고정됩니다. 탐험 종료 후 다시 구성할 수 있습니다.

- 살아 있는 아군 각각의 기본 공격·방어·보유 타이틀 스킬을 고른 뒤 **행동 확정 · 턴 진행**을 누릅니다. 선택이 하나라도 빠지면 확정할 수 없습니다.
- 보스를 포함한 네 곤충이 유효 민첩성 내림차순으로 한 번씩 행동합니다. 동률이면 아군 우선, 아군끼리는 팀 순서입니다. 행동 순서를 확정한 뒤 생긴 속도 변화는 다음 턴부터 반영합니다.
- 보스의 다음 기술과 대상은 사전에 표시합니다. 자신의 차례 전에 쓰러지면 행동이 취소됩니다. 보스가 쓰러지면 남은 행동 없이 스테이지 클리어, 아군 전원이 쓰러지면 게임 오버입니다. 마지막 보스를 쓰러뜨리면 전체 클리어입니다.
- 다음 스테이지 버튼을 누르면 생존자는 최대 HP의 40%를 회복하고 쓰러진 친구는 최대 HP의 50%로 부활합니다. HP는 최대치를 넘지 않습니다. 보호막·상태 효과·스킬 대기는 초기화합니다.
- 방어는 자신의 행동부터 다음 자기 행동 전까지 피해를 60% 줄입니다. 기본 피해는 공격력·방어력과 작은 무작위 보정으로 계산하며 회피·치명타가 있습니다.
- 스킬 사용 후 표시된 턴 수만큼 기다려야 재사용합니다. 이전 자동 대결의 HP 발동 조건과 ‘스킬 다음 턴 기본 공격’ 제한은 보스전에 적용하지 않습니다. 매 턴 직접 선택합니다.
- 회복·보호막은 살아 있는 아군을 지정합니다. 대상이 먼저 쓰러지면 시전자에게 사용하며 전투 중 부활하지 않습니다. 회복량·보호막은 대상 최대 HP를 기준으로 합니다. 보호막은 최대 HP의 40%까지 쌓이고 소진될 때까지 유지됩니다.
- 같은 버프·약화는 중첩 합산하지 않고 강한 값을 유지하며 지속 시간을 갱신합니다. 발동 턴과 다음 턴 끝까지 유지됩니다. 회피한 공격에는 적 약화가 걸리지 않습니다.
- 3배속과 **턴 결과 바로 보기**는 이미 확정된 한 턴의 표시 속도만 바꾸며 다음 턴을 자동 선택하지 않습니다. 스테이지별 최근 100개 행동 기록을 제공합니다.

### 열 보스

기존 800종 가운데 기본 HP 137 이상인 곤충 10종을 선정했습니다. 원본 도감 능력치는 유지하고 보스 전용 HP를 약 3~5.4배로 늘립니다. 아래 능력은 게임용 기믹입니다.

| 스테이지 | 곤충 | 보스 별명 | 기믹 |
| --- | --- | --- | --- |
| 1 | 구리풍뎅이 | 구릿빛 문지기 | 홀수 턴 피해 감소 35%, 관통 공격으로 완화 |
| 2 | 각시메뚜기 | 초원의 도약왕 | 3턴마다 전체 공격 |
| 3 | 날개대벌레 | 숨은 숲의 수호자 | 홀수 턴 회피율 35% |
| 4 | 남생이무당벌레 | 붉은 반격의 성채 | 3턴마다 공격자에게 7 반격 피해 |
| 5 | 검정송장벌레 | 고요한 재생술사 | 3턴마다 공격 대신 HP 8% 회복 |
| 6 | 네눈박이하늘소 | 네 눈의 추적자 | 가장 낮은 HP 비율 아군 추적, 3턴마다 필중 강공격 |
| 7 | 검정물방개 | 깊은 물의 파수꾼 | 3턴마다 HP 8% 보호막과 전체 공격 |
| 8 | 노랑선두리먼지벌레 | 황금 테의 질주자 | 짝수 턴 민첩 1.6배 |
| 9 | 검정명주딱정벌레 | 검은 갑옷의 폭군 | HP 절반 이하 공격력 +30%, 3턴마다 전체 공격 |
| 10 | 넓적사슴벌레 | 거대한 숲의 왕 | HP 절반 이하 공격력 +25%와 갑옷, 3턴마다 전체 공격 |

17개 타이틀 스킬은 `src/lib/skills.mjs`에 정의되어 있습니다. 보스전 전용 설명과 대상·대기 처리는 `src/lib/raid.mjs`에서 적용합니다. ‘질긴 생명력’은 지정 아군 HP 30% 회복과 약화 해제, ‘꽃꿀 회복’은 22% 회복과 10% 보호막, ‘철벽 갑옷’은 30% 보호막입니다. 다른 공격·필중·관통·흡수·회피·속도·약화 스킬도 직접 선택할 수 있습니다.

## 검증

```sh
npm test
npm run test:e2e
npm run build
```

단위 테스트는 실제 데이터 연결, 타이틀 근거·크기 단위, 검색, 필터 교집합, 무작위 중복 방지 및 수백 회 대결의 HP·종료 조건을 검증합니다. 브라우저 테스트는 Chromium으로 검색·분류·상세·관찰함 영속성·세 팀원 중복 방지·직접 행동 선택·지원 대상·턴 순서·클리어 및 다음 스테이지·게임 오버·모바일·정보 조회 실패 복구를 확인합니다. 보스전 규칙 테스트는 열 보스 기믹과 실제 팀의 10스테이지 완주도 검증합니다.

E2E 실행 전 개발 서버가 켜져 있어야 합니다. 기본 브라우저 경로는 `/usr/bin/chromium`입니다. 다른 환경은 `PLAYWRIGHT_CHROMIUM_PATH`로 경로를 지정하거나 Playwright에 설치된 Chromium을 사용하세요. 이 클라우드의 기본 샌드박스는 포트·브라우저 소켓을 제한하므로 서버와 브라우저 실행에 실행 도구의 권한 확대가 필요할 수 있습니다.

## 주요 파일

- `src/App.jsx`, `src/styles.css`: 페이지와 반응형 화면
- `src/lib/profiles.mjs`: 특징 근거, 타이틀 및 스탯
- `src/lib/search.mjs`: 검색·분류·정렬
- `src/BossRaid.jsx`, `src/raid.css`: 3인 보스전 화면과 반응형 조작
- `src/lib/raid.mjs`: 열 보스, 직접 행동 선택, 민첩 순서, 기믹과 스테이지 진행
- `src/lib/battle.mjs`: 이전 1:1 시뮬레이션 및 재현 가능한 난수 테스트 유틸리티
- `src/lib/skills.mjs`: 17개 타이틀 스킬, 수치·조건·설명
- `scripts/build-web-data.mjs`: 현재 저장된 이미지 목록 생성
- `data/README.md`: 수집 범위, 출처와 원문 데이터 설명
